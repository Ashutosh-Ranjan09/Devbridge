DevBridge M5 — Revised Two-Person Allocation

M5 Work Split

The LLM-versus-deterministic cut stopped balancing once GitHub and the platform APIs became core. This re-cuts the work along acquisition versus reasoning — which balances, keeps all five LLM sites with one person, and improves the testing story on both sides.

Scope 41 checks Team 2 Span 16 weeks Seam 2 contracts

01Why the old split broke

The original cut put every LLM call on A and everything deterministic on B. That was elegant while the system was mostly document logic. It is no longer viable.

Making GitHub and the competitive-programming platforms core added six external integrations, eleven GitHub checks, six platform checks, and the credential path — all of it deterministic, so all of it landed on B. Meanwhile A's work barely moved. Counted in person-weeks the old split now runs roughly 10 against 19, which is not a two-person project; it is one person with a helper.

The diagnosis

"LLM versus not-LLM" is a useful way to understand the system — it is why the check catalogue is organised that way, and it stays true. It is a poor way to divide the system, because only five of forty-one checks involve a model. Any split along that line puts 88% of the work on one side.

02The revised split

Cut between getting facts and reasoning over facts. Everything that talks to the outside world on one side; everything that runs on data already in hand on the other.

Person A

Acquisition

Every boundary with the outside world — documents in, APIs out. One coherent skill profile: HTTP clients, auth, rate limits, retries, caching, and normalising messy responses into a fixed schema.

The factoring this buys — connectors separated from rules

A writes the thing that fetches GitHub data; B writes the rules that reason about it. So G5 — "commit window versus claimed project dates" — is pure logic over a fixed structure, unit-testable from a JSON fixture with no network, no token, and no rate limit. Had one person owned "GitHub" end to end, every rule test would have needed a live API or a mocking layer. This is a better factoring on its own merits, independent of the balance argument.

A produces both. B consumes both. Nothing else crosses.

class RepoEvidence(BaseModel):
    name: str; exists: bool; is_fork: bool; owner_matches: bool
    created_at: date | None; commit_count: int | None
    languages: dict[str, int]          bytes per language
    first_commit: date | None; last_commit: date | None
    size_kb: int; is_readme_only: bool

class GitHubEvidence(BaseModel):
    handle: str
    ownership: Literal["verified_oauth", "verified_challenge",
                       "claimed_unverified", "not_found"]
    account_created: date | None
    contribution_windows: list[ActivityWindow]   server-side timestamps only
    repos: list[RepoEvidence]
    org_memberships: list[str]
    first_commit_by_language: dict[str, date]

class PlatformEvidence(BaseModel):
    platform: Literal["codeforces", "leetcode", "codechef", "atcoder"]
    handle: str; found: bool
    current_rating: int | None; max_rating: int | None
    rank_title: str | None; problems_solved: int | None
    contests: list[ContestResult]

class EvidenceBundle(BaseModel):
    schema_version: Literal["1.0.0"] = "1.0.0"
    bundle_id: str; graph_id: str
    github: GitHubEvidence | None = None
    platforms: list[PlatformEvidence] = []
    deployments: list[DeploymentEvidence] = []
    credentials: list[CredentialEvidence] = []
    registries: dict[str, Resolution] = {}
    gathered_at: str
    gaps: list[Gap] = []      what could not be fetched, and why

class Gap(BaseModel):
    source: str                   "github" | "codeforces" | ...
    reason: Literal["no_handle_in_cv", "not_found", "rate_limited",
                    "unreachable", "ownership_unverified", "no_consent"]
    detail: str | None = None
gaps is the field that makes abstention honest

Every rule that needs an absent source reads its gap and abstains with that reason attached, which flows straight into the report's "not evaluated" bucket. "GitHub activity — not evaluated: no handle found in CV" is information a recruiter needs. Without this field, a missing source is indistinguishable from a clean pass, and silence reads as approval.

04Why this split is better beyond balance

PropertyConsequence
Coherent skill per sideA is integration engineering throughout — auth, retries, pagination, caching, schema normalisation. B is pure logic and service work. Neither person context-switches between two unrelated disciplines.
B needs no network, everEvery rule test runs against committed fixtures. No tokens in CI, no rate limits, no flakiness, no API outage blocking a test run.
A needs no rulesConnectors are testable against recorded API responses. A never has to know what R-number consumes a field.
Failure isolation stays cleanA wrong report traces to a wrong claim, a wrong evidence fetch, or a wrong rule — three inspectable artefacts between input and output.
Both sides demo independentlyA can demo "here is what GitHub says about this candidate." B can demo "here is the report from this bundle." Neither demo waits on the other.
Attributable for assessmentA owns extraction and acquisition metrics; B owns detection, false-positive, and report-volume metrics. Separate chapters, separate defences.
The one cost

A now owns work that is not LLM-related — the connectors are ordinary HTTP integration. If one of you specifically wants the model-facing work and nothing else, that person takes extraction, resolution, and narrative (about 5 person-weeks) and the remainder has to be redistributed by hand. The split above is the one that balances; a strict LLM-only role does not.

Two sequencing decisions worth defending

Codeforces before GitHub. One HTTP call against a documented public API — no OAuth, no pagination, no rate-limit strategy — and it returns decisive results. A complete verification path exists by week 6, which de-risks everything after it. GitHub is three weeks of integration work and belongs after something already works.

Checkpoint 1 lands in week 7, not later. Two contracts now cross the seam instead of one, so there is more to get wrong. Scheduling the collision early is what keeps it cheap.
