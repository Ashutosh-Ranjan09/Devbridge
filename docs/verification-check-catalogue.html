Verification Check Catalogue

Every check the CV verification system performs, classified by who does it — a language model, deterministic code, or a person. Forty-three checks, five of which involve an LLM.

Module M5 — cv-verification Team 2 Span 16 weeks Trained models none

01What the system does

Corrected from earlier drafts. Internal consistency was the headline; it should have been the fallback.

Product statement

Given a developer's CV, DevBridge extracts the claims, finds the accounts the candidate names — GitHub, Codeforces, LeetCode, live deployments — and checks what they say about themselves against what those systems actually return. Where no account is verifiable, it falls back to internal consistency and credential attestation. It never claims to verify employment.

The reason this works on developer CVs and not on CVs generally: developer CVs are unusually artifact-dense. Every project carries a repository and often a live URL. Every competitive-programming claim has a public API behind it. Compare "Managed a team of 12 at Deloitte" — checkable by nobody. The vertical focus is not a market choice; it is the technical precondition that makes verification possible at all.

02The division of labour

One principle decides every allocation: machines settle facts, humans settle significance, and the model only translates between prose and structure.

LLM
5
of 43 checks
Translation only. Unstructured text into typed data, and computed findings back into prose. Never produces a number that enters a finding.
  • CV text → typed claims
  • Handles & URLs → typed identifiers
  • Self-declaration footnotes → markers
  • Entity resolution tie-break (closed set)
  • Findings → recruiter prose
Machine
32
of 43 checks
Every check with an API behind it, plus all arithmetic, interval logic, registry lookup, and structural parsing. Deterministic, reproducible, auditable.
  • All platform & repository queries
  • All date and interval reasoning
  • All registry and issuer lookups
  • All document-intrinsic logic
Human
6
of 43 checks
Everything requiring context the system does not have, plus every consequential decision. The machine gathers and presents; the person judges.
  • Interpreting attention signals
  • Seniority and substance fit
  • Assessing an explanation
  • Any contested finding
  • The hiring decision

Three tiers, and what each one licenses

TierMeaningReport treatment
decisiveAuthoritative source plus deterministic comparison. The answer is the answer.Stated as fact, with the source named and linked
attentionSignal computed reliably, but innocent explanations exist that the system cannot see.Posed as a question to a reviewer, never as a finding
evidence onlyMaterial a person needs in order to judge. No machine conclusion at all.Displayed with provenance; never scored
Decisive still does not mean automatic

"Claimed Codeforces rating 1495, API returns 1200" is settled as a fact. Whether that means a stale CV, a typo, a different handle, or a lie is not settled at all — and the consequence is never the machine's to draw. Automation ends where fact-finding ends.

Two things that make this group work

Server-side timestamps only. git commit --date= sets author dates arbitrarily; so does GIT_COMMITTER_DATE. Both live inside the repo and are attacker-controlled. Only GitHub's own record of when a push occurred is trustworthy, which is why G5 and G10 read the contribution calendar rather than a clone.

An unverified handle still counts — in one direction. A self-claimed account that contradicts the CV is strong evidence, because nobody lists a handle that undermines them. One that corroborates is weak, because it could be anyone's. So claimed_unverified accounts may lower confidence and never raise it.

Why this group matters more than its size suggests

Competitive-programming claims are among the most padded items on early-career developer CVs, and they are the only claims where a public API returns ground truth directly. One HTTP call converts "peak rating 1495 (Specialist)" from an assertion into a settled fact. Nothing else in the catalogue has that property.

04Deliberately excluded

Refusals belong in the specification, not in a footnote. Each of these is technically achievable and excluded on purpose.

IDExcludedReason
X1Entrance rank vs. published cutoffFairness. JEE and similar cutoffs vary enormously by reservation category. Without category data the check systematically flags reserved-category candidates for a rank that is entirely valid. Build it only with correct per-category tables, or not at all.
X2AI-generated CV detectionUsing a model to write a CV is not fraud — it is what a careers advisor does. Detection penalises non-native English speakers hardest for behaviour that is not wrong.
X3Identity verificationThe system cannot confirm a person exists and must not imply it.
X4Employment verificationImpossible without the employer. Activity data corroborates a period; it never confirms a job.
X5Grades and courseworkNo accessible source. Frequently the document already declares them unverified — inherit that rather than guess.
X6Any overall trust scoreCollapsing findings into one number converts an evidence report into an automated judgement, and becomes a hiring threshold within a week of shipping.

05The report

Five buckets, ordered by what a reviewer must act on. The tier of each check decides its bucket automatically, so a judgement call can never be presented as a fact.

✓
Verified
Decisive checks that passed, confirmed against a named source. Collapses to a single line — a reviewer should never scroll past twelve green rows to reach the thing that matters.
✗
Contradicted
Decisive checks that failed. Machine-certain as fact, and still requiring a person to decide what it means. At most five, ranked by confidence, each linked to its source and its span in the document.
?
Needs context
Attention-tier signals, phrased as questions. Capped at three visible, the rest behind a disclosure. Every one carries the innocent explanation alongside it.
–
Not evaluated
Every abstention with its reason. "GitHub activity: not evaluated — account ownership unverified." Silence would read as a pass.
□
Out of scope
Named explicitly — employment history, grades, identity. The reader must not infer that an unmentioned thing was checked.
The constraint that decides whether this product works at all

A recruiter gives a report about sixty seconds. If the attention bucket routinely holds twenty items, they read none of them and switch the tool off. The entire architecture is an effort to move checks out of "needs context" and into "verified" or "contradicted" — which is exactly what GitHub and the platform APIs buy: they convert judgement calls into facts. Report volume is a design metric, and it belongs in the evaluation.

Sequencing note

Platform connectors land in weeks 5–6, before GitHub. They are far simpler — one HTTP call against a documented public API, no OAuth, no pagination, no rate-limit strategy — and they produce decisive results immediately. That gives B a working, demonstrable verification path by week 6, which de-risks everything after it.

08What changed from earlier drafts

ChangeReason
GitHub and platform evidence moved from optional input to coreThey are the differentiator. Treating them as enrichment produced a generic CV verifier.
M5 owns a metadata-only GitHub componentM3's deep clone-and-analyse work stays separate. Different data at different cost — and M5 cannot wait for a module that does not exist.
Competitive-programming APIs added as a first-class sourceThe only place a public API returns ground truth on a padded claim class.
Every check carries an explicit tierPrevents a judgement call being rendered as a fact, structurally rather than by convention.
Report restructured into five bucketsFlat discrepancy lists do not survive a sixty-second read.
Entrance-rank check removedCategory-blind cutoff comparison is a bias generator.
Cross-document diff, corpus duplication, forensics-as-headline droppedSound features, wrong emphasis. Document provenance survives in reduced form as D4.
No trained models anywhereDescriptive statistics against reference distributions throughout. Removes the labelled-data dependency and keeps every finding decomposable.
