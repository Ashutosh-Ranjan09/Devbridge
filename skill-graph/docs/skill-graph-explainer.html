The Skill Graph

Module 6 takes a verification report about one developer and produces a per-skill belief: not a rating, but a Gaussian over ability that widens when evidence is thin and widens again as evidence ages. This page names every model in the layer and walks the scoring model through a real number, start to finish.

Before anything else

Three things this module refuses to do

The refusals came first and the design followed from them. Each is enforced by code and held by a test, not written down and hoped for.

Nothing here is trained. No model is fitted, no optimiser runs, no labelled data exists. Every constant is declared in a contract file with a stated reason and a sweep range. The update rule is closed-form Kalman arithmetic — arithmetic a reader can check by hand, which is the point.
There is no overall score. Ability is per-skill or it is nothing. GET /developers/{ref}/score returns 400 with an explanation, permanently. A single number would collapse an interval-valued, per-skill, decaying belief into something that reads like a credit rating.
The language model never judges. Upstream in M5 an LLM normalises CV text into structured claims. It never assigns a score, a weight or a verdict. Everything downstream of the claim is deterministic arithmetic over declared constants.

The shape of it

Six submodules, one direction

Evidence flows one way. The ontology is consulted by three stages but consulted only — it never receives. Integrity analytics reads everything and writes nothing, which is what lets it stay outside the scoring path entirely.

6.0 · event projection

Model 1 — the projection rule table

The first model is not statistical, and saying so plainly matters. It is a declared lookup table mapping each kind of verified artefact to three numbers: how strong a signal it is, how much the source can be trusted, and which skills it bears on. Nothing is inferred; the table is in contracts/projection-rules.yaml and a reviewer can disagree with any row.

The seven emit rules. strength and reliability travel on the event and enter the scoring model's variance term; nothing else about the artefact does.

Reliability factors, and why they are named on the event

Reliability is multiplied by discount factors, each of which is recorded on the event by name. A candidate who asks why a number is low gets the factor, not a total.

reliability = reliability_base × Π factors ownership_unverified × 0.6 the GitHub identity is self-claimed, not proven scraped_source × 0.7 a profile page was parsed, not an API queried aggregate_across_sources × 0.7 the claim pools a count no single source can confirm stale_evidence × 1.0 deliberately inert — decay handles age at scoring time

ownership_unverified applies only to evidence that would raise a score. A self-claimed account that contradicts the CV is credible — nobody volunteers a handle that undermines them — so the discount is asymmetric on purpose. stale_evidence exists and does nothing: applying an age discount here as well as in the decay kernel would count staleness twice, and the contract says so where someone might otherwise re-enable it.

A rule with teeth Every claim must end up either carried by an event or named in not_emitted[] with a reason. Silence is not an available outcome. This invariant is checked at projection time, and when it was added it immediately caught two claim kinds that had been vanishing without trace — a certification claim and an uncorroborated project claim.

6.1 · ontology · 6.2 · ingestor

Models 2 and 3 — the skill graph, and the absence of a model

Model 2 The volatility-tier model

Every skill is filed in one of three tiers, and the tier — not the candidate, not the evidence — fixes how fast a signal about it goes stale. Three tiers rather than a continuum, because a continuum is a parameter per skill and cannot be defended or swept.

Tierλ per dayτ = k/λtrue half-lifeExample skills
fundamental1.0 × 10⁻⁴3500 d2426 dalgorithms, C++, data structures
ecosystem3.0 × 10⁻⁴1167 d809 dPython, TypeScript, Go, SQL
framework7.5 × 10⁻⁴467 d324 dReact, Docker, PostgreSQL

Someone who could reason about algorithms in 2019 still can; a framework signal from 2023 genuinely means less. Getting a tier wrong is the difference between a skill that fades in a year and one that holds for a decade, so tiers are reviewed in a YAML file rather than set in code.

Naming discrepancy, flagged not hidden The contract calls k/λ the half-life and the API publishes it as half_life_days. Strictly it is the e-folding time constant τ: at t = τ the mean has moved 63.2% of the way back to the prior, not 50%. The true half-life is τ · ln 2 — the fourth column above. The arithmetic is right everywhere; only the label is loose, and the fix is a rename rather than a change of behaviour.

Model 3 The relation model

Twelve directed, typed edges. An edge asserts that evidence for one skill is genuine evidence about another — a strong thing to claim, so the graph is deliberately sparse and every hop is damped. The type carries the damping coefficient γ; there is one γ per type, never per edge, because per-edge coefficients are an unbounded parameter space nobody could sweep or defend.

PREREQUISITE_OF γ = 0.55 algorithms → problem_solving REQUIRES γ = 0.65 C++ → algorithms, Next.js → React RELATED_TO γ = 0.40 C++ → C (the weakest claim, most damped)

Direction matters: RELATED_TO reads symmetric and is not. Propagation only ever runs out of a skill that has direct evidence, so the arrow decides which way a signal can travel. A genuinely two-way relation is written as two edges.

No model 6.2, the evidence ingestor

Worth stating explicitly, because the gap is the design. The ingestor validates against the schema, refuses anything without consent scope skill_graph_inclusion, deduplicates by content hash, appends to a log guarded by SQL triggers that make UPDATE and DELETE raise, and quarantines skills the ontology does not know. It computes nothing. A quarantined skill is stored and flagged, never dropped — dropping it would lose evidence the ontology has merely not caught up with; scoring it would invent a node nobody defined.

6.3 · scoring engine

The scoring model, in seven parts

This is the model the rest of the system exists to serve. It is a Bayesian filter in logit space: one Gaussian belief per (developer, skill) pair, updated in closed form by each piece of evidence and widened by the passage of time. It has seven separable components, and every one of them is arithmetic you can check on paper.

S1 The latent-variable model

Ability for one developer on one skill is a latent variable θ ∈ (0,1), and the filter does not work on θ directly. It works on its logit, which is unbounded — and that is what makes the Gaussian update exact rather than approximate. Belief at any moment is two numbers and a date.

x = logit(θ) = ln( θ / (1−θ) ) the state, unbounded belief: x ~ N(μ, σ²) as of date t everything the system knows display: θ̂ = sigmoid(x) monotone, so bounds stay bounds

Working in a bounded space would need a Beta or logit-normal approximation at every step and would smear the arithmetic. Working in logit space costs one transform in and one out, and buys exactness in between.

S2 The prior

θ₀ = 0.25 → μ₀ = logit(0.25) = −1.0986 σ₀ = 1.30 → σ₀² = 1.6900 published score with no evidence at all: 0.083

A developer with no evidence is not an average developer; they are an unknown one. Centring the prior below the median is what stops silence from paying: a profile with nothing in it does not sit at 0.5 waiting to be mistaken for adequate. σ₀ is wide enough — roughly 0.08 to 0.55 in display space — that no single weak event can manufacture a score out of it.

S3 The observation model

Every event yields two numbers: what was observed, and how much to trust the observation. They come from different places, and the separation is the single most load-bearing decision in the module.

Observed value — four measurement methods

MethodUsed byMapping
percentile_against_reference platform_rating observed = a + b · ECDF(rating), with a = 0.50, b = 0.40. The empirical CDF is built once from the Codeforces user list and stored as a lookup table — a for-loop, not a training run. Reference population is developers generally, not the self-selected cohort that competes; being rated at all clears the general floor, which is what a encodes.

Observation variance — where trust lives

σ²_obs = S₀ / (reliability × relevance × strength) S₀ = 0.10

All three multipliers arrive on the event; S₀ is the only free scale constant in the whole observation model. High reliability, high relevance and high strength together mean a small variance, which means a large update.

Relevance is epistemic, and belongs here rather than in the observed value. If a repository is 40% Go, that does not mean the developer wrote worse Go — it means the repository says less about their Go. Folding relevance into the observed value would encode the first reading and quietly punish people for working on mixed codebases. Folding it into the variance encodes the second: the same claim about ability, held with less confidence.

An uncorroborated CV claim is kept out of the way by exactly the same mechanism. Its observed value is a perfectly respectable 0.45; its reliability is 0.20, so its variance is large and it barely moves the mean. The system records that the person said it, and declines to be persuaded.

S4 The update — a closed-form Kalman step

K = σ² / (σ² + σ²_obs) the Kalman gain, 0 … 1 μ′ = μ + K · ( logit(observed) − μ ) move K of the way to the observation σ²′ = σ² · (1 − K) confidence only ever increases here

The gain is the whole story: it is the fraction of the way from current belief toward the new observation, and it is set entirely by which of the two is more certain. Against the wide prior the first event carries an enormous gain; each later event carries less, because there is less left to learn. That ordering is asserted in the test suite — a reader who saw later evidence weighted more heavily than the first would be right to distrust the whole thing.

S5 The decay model

Time is not evidence, so time must never sharpen a belief. Between observations the variance grows linearly and the mean reverts toward the prior — coupled, so that one swept constant governs both instead of three independent knobs.

σ²(t) = σ²(τ) + λ_s · Δt uncertainty grows, always μ(t) = μ + (μ₀ − μ) · (1 − e^(−Δt · λ_s / k)) mean-reverts toward the prior k = 0.35, τ_s = k / λ_s reversion tied to volatility

The consequence is worth saying in words, because it is the sentence a candidate deserves to hear: a score falls with time because the system knows less, not because anyone decided the person got worse. The mean drifts back toward "unknown" and the interval widens, and both effects are visible in the explain response as a day count and a half-life.

S6 The propagation model

Evidence for C++ says something about C. Propagation is how that is expressed, and it is fenced in three ways: it runs at read time so nothing inferred is ever stored; it goes one hop; and it draws only from states that have direct evidence. Those three together make the pass non-iterative and loop-free without needing cycle detection at all.

σ²_pseudo = σ²_source / γ damping IS variance inflation then the ordinary S4 update, unchanged

Damping reuses the observation mechanism instead of adding a second one. Weak evidence and distant evidence become the same kind of thing, which is precisely why they can share an update rule. An inferred skill is presented with evidence_count: 0, basis: "propagated", and the edge it came along — never clamped, never disguised as measurement.

S7 The display model — the published number is a lower bound

score = sigmoid( μ − z · σ ), z = 1.0

What a client sees is not the mean. It is the lower end of a one-sigma interval, and this single choice does most of the ethical work in the module. A developer with thin evidence and a developer with abundant evidence can share a mean; only the second gets a high published score, because only the second's interval has closed up. Uncertainty costs the candidate something, which is the only arrangement under which gathering more evidence is the way to raise a number.

sigmoid is monotone, so a bound in logit space is still a bound after the transform. The interval always travels beside the score in every response, so it cannot be mistaken for a point estimate.

S8 The fold — how the seven parts compose

State is a derived cache and never a source of truth. Any score is recomputed from the append-only log on demand, in a total order.

state ← prior at the first event's date for each event bearing on this skill, ordered by (occurred_at, event_id): state ← decay(state → event date) state ← update(state, observed, σ²_obs) state ← decay(state → as_of)

Ordering by (occurred_at, event_id) is a total order, so two events on the same day still fold deterministically. Recomputing rather than caching is what makes three otherwise expensive things cheap: as_of queries against any past date, ablation (fold again with one event withheld, to show what it was worth), and the parameter sweep.

6.4 · query · 6.5 · integrity

Models 4 and 5 — ordering, and noticing

Model 4 The partial-order ranking model

Search does not return a ranking, because the evidence does not support one. Two candidates whose intervals overlap are not distinguishable, and printing them in an order would invent a fact. So search returns tiers: within a tier, the API says plainly that it cannot separate them.

The caller also chooses the risk posture rather than having one chosen quietly for them: definite=true requires the whole interval to clear the bar, definite=false only that the interval reaches it.

Model 5 The integrity model — nine rules that change no number

The obvious design is to spot something suspicious and discount the evidence. That is exactly what this must not do: a signal that silently moves a score is an unexplainable penalty, and with no overall trust number there is nowhere for it to hide. So 6.5 produces findings, and a test asserts the skill graph is byte-identical before and after it runs.

CheckSeverityWhat it notices

Three properties are structural. Every finding names its evidence. Every finding carries an innocent explanation — a burst of recent commits is a student finishing coursework far more often than it is anything else. And there is no "fail" severity: two values only, because a third would invite somebody to threshold on it.

Does it work?

Checking a model that was never trained

With no labelled data there is no test-set accuracy to quote, so the model is checked against a property it must have rather than a benchmark it should beat: if a true ability is known, does the filter recover it, and is the filter's own stated uncertainty honest? Three hundred synthetic developers with known ability, twelve events each, folded through the shipped code.

−0.0236bias · want |b| < 0.05
0.0510RMSE · want < 0.15
0.677±1σ coverage
0.682nominal for a Gaussian

The last pair is the result worth pausing on. A one-sigma interval around a Gaussian should contain the truth 68.2% of the time. This filter's intervals contain it 67.7% of the time — the model's stated uncertainty matches its actual uncertainty, with nothing tuned to make that happen. An overconfident filter would score well on RMSE and fail here, which is exactly why the gate checks coverage and not only error.

What the test suite actually holds

562 tests, no pytest required. The interesting ones are not the assertions that a number equals a number — they are the ones that would fail if a stated principle stopped being true: that a suppressed claim is still reported to the candidate; that the graph is byte-identical before and after integrity analysis; that one developer's evidence never folds into another's; that a quarantined skill never reaches a score.

The models themselves were audited by mutation testing — make a submodule lie, run all 562 tests, and see who notices. That found a real gap: making the ontology forget every skill's tier broke only two tests, one of which was the ontology testing itself. The scoring engine has a fallback tier list, so a broken ontology produced plausible numbers computed from the wrong half-life — the worst possible failure shape, and nothing was positioned to doubt them. There is now a test that folds identical evidence under two ontologies differing only in one skill's tier, and asserts the score, the variance and the interval width all move.
