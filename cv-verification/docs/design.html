DevBridge M5 · design record

CV Verification Engine

Verifies developer CVs against the systems the candidate names — GitHub, Codeforces, LeetCode, CodeChef, live deployments — extracting typed claims with verbatim spans and running 28 deterministic checks.

It produces no score and no verdict. It reports evidence and says explicitly what it could not check. A person decides what any of it means.

02Architecture

One package, one process. The tree reads in execution order, and each arrow is a typed contract.

ingest  →  extract  →  gather  →  rules  →  views
 bytes     ClaimGraph  EvidenceBundle  FindingsReport  what a person reads

That is what makes every stage testable alone: rules never sees a PDF, narrative never sees a URL.

Two structural rules, enforced rather than asserted

rules.py imports only pure modules. No httpx, no gather. If a rule needs data it arrives in the EvidenceBundle or the rule abstains. A test walks the AST and holds the allow-list:

PURE = {
    "cvv.models",      # the contract
    "cvv.intervals",   # the date algebra
    "cvv.ids",         # stable identifiers, no I/O
    "cvv.filters",     # pure predicates over claims
    "cvv.reference",   # curated tables loaded from data/
    "cvv.logs",        # writes to stderr, gathers nothing
}

The test also fails on a stale entry, so the list cannot rot. Before it existed, the project's own documentation claimed this enforcement and it was not there — and the rule it described had already drifted.

narrative.py cannot reach the document. The faithfulness guarantee is the function signature, not the prompt: an endpoint that cannot receive the source text cannot leak it into prose, whatever the model is asked to do.

03The contract

Nine claim kinds, from the authoritative JSON Schema. StrEnum throughout, so a typo is an AttributeError rather than a silently false comparison.

class ClaimKind(StrEnum):
    EMPLOYMENT · EDUCATION · CERTIFICATION · PROJECT · SKILL
    PROFILE              # carries the handle; 18 checks depend on it existing
    ACHIEVEMENT          # carries the directly checkable numeric
    IDENTIFIER           # the roll number → D9
    DECLARATION_MARKER   # the institution's own disclaimer

A CV date denotes a set, not a point

class FuzzyDate(Model):
    year: int = Field(ge=1950, le=2100)
    month: int | None = None
    day: int | None = None
    precision: Precision          # exact | month | year

Validators enforce that precision matches the components present, and that an exact date is a real calendar day — 31 April would otherwise raise inside intervals.bounds() during rule evaluation, far from the input that caused it.

The validator that catches most integration breakage

@model_validator(mode="after")
def _spans_index_their_verbatim(self, info) -> ClaimGraph:
    text = self.source.normalised_text
    for c in self.claims:
        p = c.provenance
        if p.char_end > len(text):
            raise ValueError(f"{c.claim_id}: span exceeds source text")
        if p.recovery is Recovery.EXACT and text[p.char_start:p.char_end] != p.verbatim:
            raise ValueError(f"{c.claim_id}: span does not index its verbatim")

What the findings model deliberately lacks

There is no overall_score field and there never will be. A single number invites a threshold, a threshold becomes a filter, and a filter rejects people for reasons nobody can inspect.

Two validators carry design decisions rather than type checks:

# An attention finding is UNCONSTRUCTABLE without its benign reading.
if self.tier is Tier.ATTENTION and not self.innocent_explanation:
    raise ValueError("tier=attention requires innocent_explanation")

# Abstention without a reason is exactly the silence the design forbids.
if self.status in (ABSTAINED, ERROR) and not self.reason:
    raise ValueError(f"status={self.status} requires a reason")

04Ingest

Three paths, dispatched on extension and on whether a PDF actually carries text.

InputPathNotes
.pdfPyMuPDF, page by pageproducer and creation metadata retained for D4
.pdf < 120 chars/page → OCRRapidOCR, opt-in extra; report carries a caveat banner
.docxpython-docx, walking body XMLtables flattened in document order
.docrefused, with its reasona different binary format; guessing loses content

Normalisation owns the definition of "the document"

NFKC folds what a PDF quietly inserts — ligatures (ﬁ → fi), non-breaking spaces, full-width digits — any of which makes an exact span match fail on text a human would call identical. An index map carries offsets back to the raw string, because after folding they no longer line up and provenance must point at the original.

Observed — DOCX

Document.paragraphs silently omits every table. A CV whose education sits in a two-column layout reads as headings with nothing under them. It does not fail: it grounds cleanly and loses half the claims.

Resolved

The body's XML children are walked directly, and each table row becomes one line — a row is one line of a CV, and splitting it would make line_at cite a cell rather than what a reader sees.

Observed — OCR

The reference CV rasterised at 150 dpi: 3,910 characters at 0.981 mean confidence. Inside that — ASHUTOSHRANJAN, IITKharagpur, KrishnaPublicSchool. Word boundaries fail, not characters.

Resolved

Grounding still holds — a verbatim is recovered from the same string. What degrades is reference-table matching, so those rules abstain rather than contradict. The report prints a banner above every bucket so a reader knows why.

05Span grounding

The model returns a verbatim; this module verifies that text really is in the document and returns where. Without it, a model that reads "rating of 1495" and returns 1595 produces a decisive contradiction against a claim the CV never made.

Two tiers, and the second needs a guard

def numerals_present(verbatim: str, text: str) -> bool:
    """Every digit sequence in the verbatim must occur in the document, as a whole run."""
    present = set(_NUMERALS.findall(text))
    return all(n in present for n in _NUMERALS.findall(verbatim))

Measured: a hallucinated rating of 1800 where the document says 1495 scores 0.944 on partial-ratio and sails through a bare 0.92 threshold — three characters out of fifty-three. Similarity is blind to precisely the character that matters, and numbers are where the decisive checks live.

Whole runs, not substrings. A substring test lets "rating of 149" through against a document saying 1495 — dropping a digit is a one-character edit, exactly what the fuzzy tier forgives and exactly what this guard exists to refuse.

The window is a boundary, not a hint

if window is None:
    lo, hi = 0, len(text)
else:
    lo = max(0, window[0] - WINDOW_MARGIN)   # 64 chars of slack
    hi = min(len(text), window[1] + WINDOW_MARGIN)

A margin, not a fallback. Given a 180-character education section, the model returned "SKILLS AND EXPERTISE" and "EXTRA CURRICULAR ACTIVITIES" as degrees; a document-wide search found that text elsewhere and grounded both.

Token-shaped fields are recovered, not trusted

Handles, repo owners, credential ids, roll numbers and URLs must each be a literal substring of the document, taking the document's casing. A model works in tokens and normalises: it returns ar-009 for AR009, the API 404s, and the report says a real account does not exist.

The search is scoped to the claim's own span with no fallback. A real CV carried handle: AR009 (Codeforces) and handle: ar009 (CodeChef) two lines apart; a document-wide search returned whichever appeared first.

06Extraction

Eight narrow passes, each over a scoped window. The model proposes; deterministic code decides what is real.

PassWindowProduces

projectsrouted sectiontitle · urls · dates · technologies

required is the lever

A single call with every field optional returned 18 claims carrying kind and verbatim and nothing else — the model segmented the document and populated none of it. Four narrow calls with required in the JSON Schema returned every value correctly. Grammar-constrained generation makes an optional field one a small model will skip.

The model routes the sections, not a keyword list

Observed

sections=("ACHIEVEMENT", "AWARD") encodes what one CV called its section. A second document headed it "COMPETITIVE PROGRAMMING", matched nothing, fell back to the whole document, and lost two of three ratings and the only contest rank — silently, on a CV that had done nothing wrong.

Resolved

The model is shown the headings and says what each holds; the answer is verified against headings the document actually has. Keyword lists survive only as a fallback, so routing can improve a window and never break one.

Two refinements each cost a debugging round:

  • One window per contiguous run, never one overall. The reference CV routes both EDUCATION and COURSEWORK INFORMATION to education — correctly — and they sit at opposite ends of the page. Spanning them turned a 180-character window into a 4,252-character one. Choosing between them was the next wrong answer: longest-first picked COURSEWORK and lost every degree.
  • A category the model needs must exist even if no pass consumes it. With no coursework category, coursework went to education, and the education pass turned "Computer Science" into a degree awarded by "University".

Ask the right question

The skills pass returned the CV's own category headings as skills — programming languages, utilities — and the plan was an ontology lookup to filter them. Not needed: asking "what category is each item" instead of "list the skills" made both models exclude headings by themselves, because a heading has no plausible category. Junk output is often a task-framing problem before it is a capability one.

Do not ask for a verbatim you can derive

The skills and handles passes return no verbatim at all. Asked for both a name and a verbatim, the model sets them equal and returns the whole line as the skill name; asked for a handle and a verbatim it composes one — it returned "Codeforces: AR009" for a document that says "(handle: AR009)", and grounding dropped it along with ten other proposals.

A handle is then located on a line that names its own platform. This CV carries AR009 on its Codeforces line and ar009 on its CodeChef line, so a window-wide search gave both claims the Codeforces line the moment the model miscased one. Every field individually real; the pairing silently wrong.

What still uses a regex, and why

Five patterns became model passes because each encoded how one document happened to be phrased:

PatternReturned nothing on
round\s+#?(\d{2,4})AtCoder, LeetCode, ICPC, even "Round 2"
\d{2}[A-Z]{2}\d{5}every institution but IIT Kharagpur
could not verify|self-declaredany institution wording its footer differently
(platform)…handle:\s*(\w+)Codeforces: ar009, a bare URL, a bracketed name

Two remain and both earn it. GITHUB_REPO, because a URL's grammar is declared by the internet and not by a CV. PLATFORM_MENTION, which is enforcement rather than parsing and is built from the contract's Platform enum so it cannot drift out of it.

Roll numbers are still found by pattern, but the patterns come from the same data file that interprets them — adding VIT Vellore as a data entry made 21BCE1847 decode end to end with no code change.

07The deterministic gate

Grounding proves a claim's text is real. It does not prove the model classified that text correctly — and misclassification produces false decisive findings just as readily as hallucination.

Observed — the headline failure

Given the whole CV, the model found one achievement — Codeforces 1495 Specialist — and emitted those same field values against fourteen different verbatims, including the CV's name header.

Why grounding cannot catch it

Every verbatim is genuine and 1495 is a genuine rating. Only the pairing is invented. Checking the document is not enough — the number has to be in this span.

def value_is_in_its_own_span(claim: Claim) -> bool:
    if claim.value is None:
        return True
    return numbers_in(str(claim.value)) <= numbers_in(claim.provenance.verbatim)

As whole numbers, with grouping commas removed. Version 1 asked str(value) in verbatim, so a value of 10 "appeared" in "Ranked 1106" — a model truncating a number passed the very check that exists to catch it.

FieldRule
valuethe number must appear in this claim's verbatim
platformwhichever the verbatim names; none named → unattributable, dropped
proficiencythe band the sentence uses, or None. Never invented
two or more platforms namedflag aggregate_across_sources; the rule abstains

The model labelled a CodeChef rating codeforces, which would have compared 1733 against Codeforces' 1495 and fired a decisive contradiction against an honest candidate. It also labelled four skills expert — a word appearing nowhere in the CV.

The other three stages

  • Excluded exams — read from the verbatim, never the model's label.
  • Semantic deduplication, keyed on meaning rather than span: the model returns the same claim with slightly different verbatims, which ground to different offsets and survive a span-keyed dedup. Five copies of one rating got through that way.
  • One region, one kind. Two container claims over the same text is a classification conflict, and the more specific kind wins.

The drop counts are not decoration — they are the extraction-quality metric, and they travel into the report.

08Dates and intervals

No dateutil: it is permissive by design and reads 2022-26 as June 2022 — a confidently wrong precision, which is worse than a failure.

The slash-date problem

Observed

A third CV had five roles in MM/DD/YYYY. All five parsed to nothing, and D5, D10, D11 and D12 all abstained "fewer than two dated roles" — the entire employment group disabled by one date format.

Resolved

Nothing in 02/05/2024 says which field is the month. The rest of the document does: a CV writing 01/26/2024 anywhere has shown its hand, because 26 is not a month.

Where nothing is decisive — or where the evidence conflicts — the date parses to the year. The year is certain, the month is a coin toss, and a wrong month can raise a DEFINITE overlap and contradict somebody where a year-precision interval never can.

Three-valued interval algebra

SpanDefinitionMeaning
core[start.latest, end.earliest]covered under every reading
max[start.earliest, end.latest]covered under some reading
cores intersect          → DEFINITE     (scorable)
only max spans intersect → POSSIBLE     (context, never scored)
neither                  → NONE

Only DEFINITE may raise a scoring discrepancy. A single-year interval has an inverted, empty core — "2021" has start.latest 2021-12-31 after end.earliest 2021-01-01 — and can never be DEFINITE. That emptiness is the mechanism, not a defect.

Live example: CF-Connect [May '25 – Jun '25] against Dijkstra Visualizer [Jun '25]. Both cover June, so a naive comparison reports a contradiction; the two could equally have run Jun 1–10 and Jun 20–30, and the document does not say.

today is injected everywhere. Nothing reads the clock — a verification must reproduce when re-run, and a report stored in March must still explain itself in September.

09Evidence gathering

Every outbound request lives behind one module. Every failure path writes a typed gap and gathering continues: one dead source must never fail the bundle.

ConnectorSourceFeeds
Codeforcespublic API, no authP1 P2 P3
LeetCodepublic GraphQL, no authP4
GitHubREST + GraphQL contributions calendarG2–G11
HTTP livenessone GET per claimed deploymentW1
CodeChefthe public profile page, scraped — no API existsP5

CodeChef's evidence is marked source_quality: scrape, and P5 is attention-only for that reason. A field the page lacks is None, an unrecognised page is a gap, and a missing handle is a finding only when CodeChef redirects the profile URL to its homepage — any other redirect means the site changed, and says so.

Server-side timestamps only

git commit --date= and GIT_COMMITTER_DATE are attacker-controlled. Only repo.created_at, pushed_at and the contributions calendar are trustworthy; where no server-side value exists the field stays null and a gap opens. RepoEvidence.first_commit is therefore permanently None.

Two connector details that are easy to get wrong

  • LeetCode's acSubmissionNum carries "All" alongside the per-difficulty rows. A naive sum gives 253 + 60 + 141 + 52 = 506 — exactly double. That inflates the observed count, making an honest claim look understated.
  • LeetCode publishes a live rating and no peak, so it is stored as current_rating with max_rating left None. Storing it as a peak would let P4 call someone an overstater for a rating that has since fallen.

Twenty-seven checks, each a frozen dataclass registered by decorator, each declaring its tier and whether it may move a number.

Three control signals

Two worked examples

D5 — the handover band. A professional CV gave exact dates for the first time:

Curebase / Quotient    56 days, 22%  →  ✗ contradicted   (two months of dual full-time)
Quotient / Stewards    13 days,  5%  →  ? needs context  (a notice period)

Absolute days, not the fraction — a two-week handover between two one-month contracts is 50% of the shorter role and still a handover.

P2 — contest identity, platform-agnostic. The identity of a contest is its largest number; divisions and stages are small, and a year appears in the platform's record rather than in what a CV copies.

11The report

Five buckets, and the fifth is what makes the other four honest.

✓verifiedchecked against an outside source, no discrepancy — plus corroboration notes
✗contradicteddecisive findings, capped at 5, ranked by confidence
?needs contextattention findings, always printed with the innocent reading
–not evaluatedevery abstention, with its reason
□out of scopethe static exclusion list, always present

A reviewer gives a report about sixty seconds; the caps are a design constraint, not a preference.

section_confidence is a probability of contradiction, not a grade

combined = 1.0
for finding in group:
    weight = 1.0 if finding.tier is Tier.DECISIVE else ATTENTION_WEIGHT  # 0.4
    combined *= 1.0 - finding.confidence * weight
confidence = 1.0 - combined

Three things stop it becoming the score this system refuses to produce: non-scoring findings never contribute; a section with no scoring finding is absent, not zero — zero reads as "measured, found nothing" and gets averaged; and nothing is combined across sections.

The tier weight is not decoration. Discrepancy.confidence says how sure we are of the observation: P2 recording rank 1109 against a claimed 1106 carries confidence 1.0, because the API definitely says 1109. Raw confidences drove an honest CV's achievements section to 1.0 on a three-place standings artefact. Weighted, it reads 0.4.

Coverage describes the verification, not the candidate. A high number means "we checked thoroughly", never "they are good" — so it cannot become a hiring threshold.

12The narrative

The second and last place a model is called. It does not write a briefing — it writes one sentence per finding, and Python assembles the frame.

Observed

Asked for free prose over a report carrying four attention findings, the model opened with "the CV does not contradict any rules, as all claimed information is verified" — a verdict, from a system whose first principle is that it produces none. It passed a numeral check because it contained no numbers.

Resolved

A model that never writes a global sentence cannot write a false one. It now produces one sentence per finding; the counts, the ordering and the innocent readings are printed by Python.

LayerWhat it stops
signaturenarrate(report, provider) — cannot reach the document, so cannot introduce a fact nobody computed
omission checkevery finding must get a sentence — omission is how version 1 lied
containmentnumerals checked per finding, not per report

Per-finding containment matters: a number belonging to P1 inside a sentence about G5 is the extraction failure arriving at the other end of the pipeline, and a report-wide check would pass it. Asked to include the benign reading, the real model copied the headline and dropped it — so that guarantee cannot depend on a model remembering.

13The manual-check worksheet

Naming what a machine cannot do and stopping there is useless: a reviewer told "the degree was not verified" still has to work out which institution, which roll number, and what to ask.

cvv verify --worksheet emits the question, whom to ask, the roll number already decoded, and what the machine already established — and it invents nothing.

Observed — its first output

It asked a candidate how two of nineteen proposed claims came to be dropped by our extractor, why their own placement cell wrote a disclaimer, and to account for a gap in their dates.

Resolved

A non-scoring finding never becomes a question for the candidate. scoring=False marks findings describing the extraction, the document, a career's shape or a naming habit — none is a claim the candidate made.

A verification contact is printed only where the operator supplied one in data/institutions.json, which ships empty: a guessed registrar address sends a candidate's details to a stranger, so an unlisted institution gets its office named by role instead.

14The handoff to M6

M6, the skill graph, lives beside this module in ../skill-graph and reads one file: the contract's VerificationReport, which cvv verify --save DIR writes as verification-report.json and GET /v1/verifications/{id} returns.

One function, pipeline.verification_report(), builds it for both, so the file and the response cannot drift apart. It computes nothing: status, coverage and provenance are read off the stages that produced them.

This module does not decide what evidence is worth. An earlier events.py projected the report into M6's evidence events itself. M6 has its own projector, and what a verified artefact means for a skill is a skill-graph judgement — so ours was a second answer to M6's question, and it sent skill ids in a surface: namespace that M6 quarantined, all thirteen. It is gone.

The first real handoff failed at every step, and each failure was invisible until a real report crossed the boundary:

What brokeWhy nothing caught it
the report had no evidence bundle, subject, provenance or coveragethe contract test parsed the stages, never the whole report
M6 refused document.created_at = D:20250704194743+05'30'jsonschema checks format: date-time only with an optional package
two fields were extensions nobody had listedNarrative was not among the models the test compared

The contract test now builds a full report over real evidence and requires it to validate except for the named extensions — including inside oneOf branches, where a github block carrying extensions surfaces as "valid under none of the schemas".

The spec draws three services; this system collapsed them by explicit decision. The two boundaries the split existed to enforce survive: /v1/narrate accepts only a FindingsReport, /v1/evaluate only a ClaimGraph. Neither can reach the document, whether the call crosses a network or a stack frame.

DecisionReasoning
No queueBackgroundTasks runs the job here. Honest for one process, first thing to replace when it is not
completed_degraded must mean something"any gap" was useless — before its scraper, CodeChef was a gap on every run, so every report was degraded. It now means something transient stopped a check
A failure is still a reportempty claims and findings, not absent — a client never needs two shapes, and a vanished verification leaves them with nothing to tell the candidate
501, not an empty successan empty result reads as "resolved to nothing" rather than "never attempted"

Persistence — two stores, one Protocol

JSONB, not an ORM. The stored object is the report itself — a deep pydantic tree that already round-trips through JSON by contract — so shredding it into columns would create a second schema to keep in step with the first. Columns hold only what is queried, including the idempotency key under a partial UNIQUE index, because two concurrent retries of one upload cannot be settled by a check-then-insert.

Observed — one suite, both stores

A duplicate idempotency key made memory quietly rebind the key to a second verification, while Postgres raised a UniqueViolation that reached the client as a 500. Registering one webhook twice made memory fire it twice per verification and Postgres fire it once.

Why it was invisible

The Protocol makes mypy check they have the same shape. Only a suite running against both checks they have the same behaviour — and they did not.

Local, not hosted — decided. A stored report holds a real person's name, roll number, institutions and handles, so where the database lives is a question about consent rather than infrastructure. A hosted Postgres would need no code change, which is exactly why the decision has to be deliberate.

16Cross-cutting

Logging never carries the CV

A log line is the easiest place for personal data to escape — written to disk, shipped to an aggregator, tailed in a shared terminal, kept long after the verification was deleted. Events carry identifiers and counts, never content.

Stable identifiers

claim_id   = "c" + sha1(f"{graph_id}|{char_start}|{kind}|{discriminator}")[:10]
finding_id = "f" + sha1(f"{report_id}|{rule_id}|{','.join(sorted(claim_refs))}")[:10]

The discriminator is load-bearing: one skills line yields several claims sharing a span and a kind, and without it they collide onto one id and all but one vanish.

17How the system is measured

A unit test proves a rule does what its author intended, using a fixture that author wrote to exercise it. It cannot prove the system catches a falsified CV.

The mutation harness takes a real document that ran end to end, corrupts exactly one fact, and asks whether the check responsible notices. Seventeen mutations across 15 rules — two each for P2 and P5.

MeasureWhat it says
Detectionthe quotable number, and the easy one to inflate. "Something fired" does not count — the rule responsible must be the one that noticed
Collateralrules firing on a mutation they had no business noticing. The honest one

Three refinements make the numbers honest: baseline findings are subtracted and named; a mutation the document cannot carry is skipped, not failed, or the rate measures the document rather than the system; and an abstention is not a miss — counting it as one would make detection a measure of how well-connected a candidate is.

What it found

  • P3 compared every problems_solved claim against Codeforces, whatever platform it named. "Solved 800 problems on LeetCode" on an honest CV was decisively contradicted by a Codeforces count of 412 — the exact failure P3's own docstring warned about, committed one level up.
  • D11 reported a career gap between two mentions of the same role. That is D10's finding; a document contradicting itself does not also have a gap.

Reproducibility, and its limit

Within one model load it is exact: four consecutive extractions of the same CV were byte-identical. Across loads it is not. Ollama picks the GPU/CPU layer split from whatever VRAM is free at load time — the same machine reported 100% GPU and later 81% in one session. The filters absorb that variance usually, not always: an audit found a live extraction assertion failing once in three runs.

18Deliberately not built

ExcludedWhy
Entrance rank vs. cutoffJEE cutoffs vary by reservation category; a category-blind comparison systematically flags reserved-category candidates for a rank that is entirely valid
AI-generated-CV detectionusing a model to write a CV is not fraud, and detection penalises non-native English speakers hardest
Contribution authenticity (G12)see below
Identity, employment, degree, CGPAno accessible source. A degree can only be confirmed by the institution that awarded it
Any overall trust scorea number invites a threshold

G12 in detail — excluded, not backlogged

Cost was never the objection: GraphQL returns 100 commits a query, roughly 40 for a whole account.

It does not work in either direction. Farming: 400 commits with a median of one line is a cron job, and it is also fix: typo in README / refactor: rename userId / test: add empty-input case — the atomic-commit habit the industry teaches. Bulk import: one honest npm install writes package-lock.json +14,203 −0, which is the signature.

And it is shaped wrongly, which decides it. Every other rule tests a claim — P1 tests "peak rating 1495", G7 tests "this is a project". G12 tests no claim: the CV never says its author's commits are of representative size. There is nothing to contradict, only a habit to be suspicious of. It is also defeated by random.randint(1, 400), so it selects for naive GitHub usage — students, deadline pushes, and people whose real work is private.

19Open decisions and known gaps

Nine fields ahead of the contract

Twenty-five of the twenty-seven schema definitions set additionalProperties: false, so a field added here makes our output invalid for a consumer validating against the schema. Nine exist, each load-bearing:

FieldNeeded by
ExtractionMeta.filteredD2 2.0 — filtered ≠ ungroundable
RepoEvidence.authored_files / authored_bytesG7 2.0 — a lock file is not substance
RepoEvidence.homepageW1 2.0 — ties a deployment to its repo
GitHubEvidence.public_repos / public_repo_countskills a CV cannot fit
RuleOutcome.notewhat a corroborating rule confirmed
Narrative.rejected_becausewhy the model's prose was not used — never listed, because Narrative was not compared
VerificationReport.failurewhy a verification failed; the contract has no field for it

A test holds them as a named list and fails on anything else — and also fails if an entry stops being an extension, so the list cannot rot. The integration spec predicted this failure mode verbatim: "one person adds a field locally, the other never sees it, and integration breaks in week 7."

Arguably the strongest reading is that the spec itself prescribes schemas/*.schema.json — generated from Pydantic, committed, which makes the models the source of truth and the upstream draft what should be regenerated.

Honest gaps

  • No gold set. Phase 5 specifies two instruments: a mutation engine (built) and a gold set measuring extraction precision and recall per claim kind (not built). Extraction accuracy is unmeasured; only rule detection is.
  • Three documents is a small corpus, and one is synthetic. Each new document has found a real bug within minutes.
  • A small model. Several documented failures are qwen3:1.7b's limits rather than the design's, and a larger model is the intended upgrade path.
  • G6 tier 2 is deferred by decision: reading repository files opens a prompt-injection surface whose contents the candidate chooses, for a gain the manifest check already approximates.

20The invariant

A CV from someone with no account, no repositories and no contest history must still produce a complete, honest report.

All eleven document-intrinsic checks need no network at all, so the document-only path is a real path rather than a failure mode. cvv verify --offline is that path, and a test asserts every rule still appears in the report with its reason.

Everything else follows from this: abstention is a first-class result, and evidence gathering lives inside this system rather than arriving from somewhere else.
